Workshop: Connect, Secure, Protect, and Observe with Connectivity Link

1. Purpose

This hands-on workshop guides platform engineers and application developers through service onboarding using Gateway API and Connectivity Link policies. Participants deploy an API, expose it through a Gateway, authenticate callers, apply per-user limits, inspect policy status, and explore monetization options.

The workshop uses the visual Showroom theme used by Open Demo days. Ready-to-apply manifests, scripts, prerequisites, and instructor notes live in the Workshop guide.

The application labs require an OpenShift/Kubernetes cluster with Connectivity Link (Kuadrant components) and a Gateway API provider installed and healthy. Operator installation, public DNS, certificates, and billing credentials are environment-specific and must be prepared before attendees start.

2. Learning objectives

After the workshop, participants can:

  • Explain the roles of GatewayClass, Gateway, HTTPRoute, and policy resources.

  • Route HTTP traffic to a Kubernetes Service.

  • Require API-key authentication and observe 401 and 403 responses.

  • Apply per-identity rate limits and observe 429 responses.

  • Read status conditions and troubleshoot common attachment and policy issues.

  • Compare usage visibility, billable event ingestion, AI inference billing, and API analytics.

3. Protect

Apply authenticated RateLimitPolicy rules.

Alice and Bob have different request limits.

4. Platform guardrails

Apply a Gateway-level default-deny policy and inspect scope/status.

Unprotected routes inherit the platform guardrail.

5. Monetize

Compare a Grafana estimate with Lago, Platform Billing Operator, and Moesif.

Participants distinguish monitoring from durable billing events.

6. Verify and clean up

Run verification scripts and delete lab resources.

Expected behavior is reproducible and temporary resources are removed.

4. Before the session

Use the Workshop guide to prepare the cluster. Platform operators complete installation and health checks before attendees begin. For the platform workflow, see Platform Engineer workflow.

5. Lab files

The repository includes ready-to-apply YAML under workshop/manifests/, verification scripts under workshop/scripts/, and the four monetization options under workshop/monetization/.

  • Developer workflow provides an additional OIDC onboarding scenario.

  • Monitoring and observability covers dashboards and the console plugin.

  • Monetization labs explains the four usage and billing patterns.

6. Instructor guidance

Allow approximately three hours for the core workshop. Add time for the monetization labs based on the selected integration. Keep sample API keys and test billing data confined to isolated environments. Public DNS, production ACME, payment processors, and real customer traffic are outside the core attendee setup.
