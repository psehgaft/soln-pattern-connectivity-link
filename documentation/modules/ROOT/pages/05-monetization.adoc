= Monetization workshop: from traffic to usage
:sectnums:
:sectlinks:
:doctype: book

== Purpose

This module adds monetization patterns to the Connectivity Link labs. It distinguishes an operational usage estimate from a durable billable event and compares four routes: ConfigMap/Grafana, Lago, Platform Billing Operator, and Moesif.

See the complete https://github.com/psehgaft/soln-pattern-connectivity-link/tree/main/workshop/monetization[step-by-step monetization guide^], including Grafana dashboard files and scripts.

== Four options

[cols="1,2,2,2"]
|===
|Option |What participants build |Best fit |Key boundary

|ConfigMap + Grafana
|Request-rate, status-code, and sample estimate panels based on Istio metrics.
|A basic usage demonstration and operational visibility.
|An estimate only; scraped counters are not an invoice ledger.

|Lago
|A billable metric and five synthetic usage events with unique transaction IDs.
|Subscription and event-based usage billing.
|A durable asynchronous producer must map trusted usage to customers and retry safely.

|Platform Billing Operator
|A PriceBook and Plan reconciled into Kuadrant policies in an isolated evaluation cluster.
|OpenShift AI Models-as-a-Service billing and enforcement.
|The linked 0.0.1 package is an experimental evaluation path; verify maturity and compatibility.

|Moesif
|A test Envoy WASM capture integration and meter in a non-production environment.
|API analytics, metering, quotas, and billing workflows.
|The plugin is external to Connectivity Link; validate mesh and gateway compatibility.
|===

== Lab sequence

. *Basic dashboard:* verify the `istio_requests_total` series, apply a ConfigMap with an illustrative rate, render the dashboard, and send test requests.
. *Lago:* create a test metric/subscription, set a test API key outside Git, emit five uniquely identified events, and inspect usage in the test tenant.
. *Platform Billing Operator:* review package/support status, apply a future-dated PriceBook and Plan in an isolated cluster, and inspect compilation conditions and policies.
. *Moesif:* identify Gateway proxy labels, render the WASM plugin without committing the Application ID, send test traffic, and inspect captured events.

== Expected outcome

Participants can select a pattern based on whether the goal is visibility, usage-event billing, AI inference billing, or API analytics and monetization. They can explain how identity, retries, duplicate prevention, data retention, masking, and customer disputes change the design.

[WARNING]
====
Do not treat Grafana estimates as billing truth. Use test customer/subscription/account data for Lago, Platform Billing Operator, and Moesif exercises. Never commit API keys or customer traffic. Review body capture, data residency, retention, and privacy controls before integrating real API telemetry.
====


== OpenShift validation: Lago, Grafana, and the Console

The workshop environment reached a deployed Lago release on OpenShift using chart `2.1.1`. API, migration, and frontend images were built to the cluster's internal registry. The frontend needed an OpenShift-compatible image because the upstream container attempted to write under its document root and nginx cache, bind to port 80, and create `/run/nginx.pid`. The reusable Dockerfile prepares writable paths, listens on `8080`, and stores the PID at `/tmp/nginx.pid`. The Helm release reported `deployed`; its migration Job completed, and the frontend Service endpoint was ready on port `8080`.

Use the [environment template](https://github.com/psehgaft/soln-pattern-connectivity-link/blob/main/workshop/monetization/env/workshop.env.example), [OpenShift build/deploy material](https://github.com/psehgaft/soln-pattern-connectivity-link/tree/main/workshop/monetization/openshift), and [Grafana dashboard template](https://github.com/psehgaft/soln-pattern-connectivity-link/blob/main/workshop/monetization/grafana/api-usage-billing.json). Namespace, image tags, internal registry, Routes, datasource, metrics job, and example price are cluster-specific values. Never commit an API key or private Lago values file.

=== Confirmed versus pending

[cols="1,3"]
|===
|State |Evidence

|Deployed
|Lago Helm release reported `deployed`; API, frontend, worker, clock, Redis, and database pods were Running. The migration Job completed, and the frontend Service had a ready endpoint.

|Verified separately
|The PostgreSQL 15 `getlago/postgres-partman:15.0-alpine` test endpoint reported `pg_partman` default version `5.4.0`. This does not alone establish which database URI Lago is using.

|Not end to end
|Lago login, API-key creation, and billable-event ingestion were not confirmed. An attempted event request received HTTP 401 because the key was empty/invalid.

|Metrics pending
|Grafana's Thanos datasource resource was inspected, but a direct Thanos query returned HTTP `000`. Validate series and labels in Grafana Explore. HTTP `000` means the request did not complete; it does not establish that usage is zero.

|===

=== Grafana API usage and estimated value

The dashboard route observed in this environment was:
https://api-usage-api-observability.apps.cluster-p6pgn.dyn.redhatworkshops.io/d/api-usage-billing/api-usage-and-cost-estimate?orgId=1&from=now-1h&to=now&timezone=browser&refresh=30s

Use your cluster's Grafana route if it differs. The observed datasource was named `Thanos`, backed by `https://thanos-querier.openshift-monitoring.svc:9091`, and selected Grafana instances with `dashboards=grafana`. The dashboard template exposes the metrics job, reporter, destination service, API user, application, example unit price, and currency. Confirm labels and data in Grafana Explore before interpreting any panel.

The price panel estimates `request count × example price`; it is not Lago-rated usage, an invoice, or a payment record. Do not describe this setup as end-to-end monetization until Lago accepts a test event and displays it against a test subscription.

=== Connectivity Link in the OpenShift Console

The `kuadrant-console-plugin` was present and running in `kuadrant-system`, and was enabled through the cluster Console operator. Confirm with:

[source,sh]
----
oc get console.operator.openshift.io cluster -o json | jq '.spec.plugins'
oc get consoleplugins.console.openshift.io
oc get pods -n kuadrant-system | grep kuadrant-console-plugin
----

Refresh the OpenShift Console after enabling it. The plugin provides Connectivity Link/Kuadrant views for gateways and policies; it is separate from Grafana's monetization dashboard. An embedded custom monetization page inside the OpenShift Console was not implemented or verified.
